# english-reader

一个 Claude Code skill：你自己选一篇英文（小说章节、短篇、新闻、演讲、评论随笔、科普），它按你的英语水平做成中文讲义，帮你读下去、读懂。主线是拆长句：每章挑几句长难句，一句拆成一张两栏的表，左边是英文的意群，右边是按英文顺序读下来的中文。

## 它做什么

| 能力 | 你得到什么 |
| --- | --- |
| 看难度 | 先摸底，看两头：生词大约占多少，30 词以上的长句占多少。建议直接读、拿来练拆句、配讲义读，还是偏难（降一档、换一篇或精读）。读什么由你定，它不选书 |
| 轻读（默认） | 每个单元读前半页：背景、新出场的人物、本章反复出现的词。读后不超过 3 页：长难句（精讲 2 句，练习 2–3 句）、2 道理解题、2–3 个词条、1 道复述题 |
| 精读 | 读前半页，加完整讲解：长难句（断句表、卡点、译文，可加怎么拆、句型和仿写、延伸、赏析）、词的用法、一个语法点、赏析、写作、自测。整本、整篇或挑几章 |
| 拆句 | 每句长难句：一个问题（谓语是哪个词、it 指什么）、断句表、答案。精讲句再讲最挡路的一处（卡点）和译文。每句标 1–2 个结构标签，从 12 种里选，如主谓隔开、it 占位、独立结构 |
| 难句本 | 把各章的长难句和卡句按结构标签汇总成一本。前半只有原句和问题，自己拆；后半是讲解 |
| 单词本 | 读前的词、词条、句子里注的词，汇成一张表，附原句和章号 |
| 卡句 | 读的时候卡住的句子记进 `卡句.txt`，注明“词都认识”还是“有生词”。下次做讲义时先讲这些句子 |
| 复述反馈 | 写几句英文复述，它指出理解偏差和两三处语言问题 |
| 产出 | Markdown；可选 PDF 小册子；难句本和单词本可导出 TSV，给 Anki 一类的工具 |

讲义里的每段引文都和原文逐字核对过，断句表连起来和原句一字不差，词典行对照词典核过音标和语体标签，写完还有一个没参与写作的代理独立审稿。不翻译全文，不替代词典。

效果见 `demo/`：《柳林风声》第 1 章（精读）和第 2 章（轻读），B1 水平。先看 `demo/讲义/第02章.md` 和 `demo/难句本.md`。`demo/讲义.pdf`（44 页）和 `demo/难句本.pdf`（23 页）是第三版排的。

## 安装

```
# 办法一：直接 clone 到自己的 skill 目录
git clone https://github.com/liyafly/english-reader.git ~/.claude/skills/english-reader

# 办法二：clone 到任意位置，再用安装脚本建一个软链接过去（macOS、Linux）
git clone https://github.com/liyafly/english-reader.git && cd english-reader && ./install.sh
# 卸载：./install.sh --remove
```

不想安装也能用：在 Claude Code 的对话里让它读这个目录的 `SKILL.md`，照着做。

## 用法

装好以后：

```
/english-reader book.epub 第 1–3 章
/english-reader book.epub 第 1–10 章，第 3、7 章精读，要 PDF
/english-reader article.html 水平 B2
/english-reader 这句没看懂：……
/english-reader 出难句本和单词本，要 Anki 文件
```

没装时，在对话里说：

```
按 english-reader/SKILL.md，帮我读 article.html，水平 B2
```

| 参数 | 可选值 | 默认 |
| --- | --- | --- |
| 文本 | txt、html、epub 的某几章、网址，或直接贴 | 必填 |
| 水平 | CEFR：A2、B1、B2、C1 | 没说会问你一次 |
| 模式 | 轻读；精读：全部，或指定单元 | 全部轻读 |
| 文体 | 小说、新闻、演讲、评论随笔、科普，或自动判断 | 自动 |
| 赏析、写作 | 开、关（只对精读单元） | 开 |
| 审稿 | 开、关（关掉会快，错误会明显变多） | 开 |
| PDF | 开、关（讲义和难句本） | 关 |
| Anki 文件 | 开、关 | 关 |

做的过程：抽出纯文本 → 摸底 → 定计划（精读的计划先给你看；轻读不给，免得剧透）→ 写 → 脚本检查 → 独立审稿 → 核词典 → 出 Markdown、难句本、单词本（要了才出 PDF）。

**读讲义。** 先看读前，再读原文，读完做长难句：先答问题，再看断句表。拆完的句子，按正常速度再读两三遍。

**记卡句。** 在项目目录的 `卡句.txt` 里一行记一句，只记开头四个词以上也行。行尾可以加 `｜词都认识` 或 `｜有生词：词, 词`（半角 `|` 也行）。用一行“第 2 章”说明下面的句子在哪一章，不写就全书找。也可以直接贴到对话里，它替你记。例子见 `demo/卡句.txt`。

**PDF 的版式。** A5 小册子。断句表用下置排法：断句占满栏宽，顺读在表下排成一段，各块标 ①②③。左右对排时 demo 第 2 章有 21% 的断句行折行，所以不用。章内不印问题和答案；自己先拆，用难句本。

## 导入 TSV

`难句本.tsv`、`单词本.tsv`：制表符分隔，UTF-8，一行一条，没有表头行，格子里没有制表符和换行。各家工具都能当表格导入。

要导入 Anki，让它加 `--anki`，另出 `难句本-anki.tsv`、`单词本-anki.tsv`。开头几行是 Anki 的文件头（分隔符、列名、id 列；难句本还有标签列），Anki 2.1.54 起认得。在 Anki 里「文件 → 导入」，把各列对到笔记类型的字段。难句本建议正面用原句、注、试，背面用其余。id 不随句子编号变，讲义改了重新导出、再导入，Anki 按 id 认出已有的卡。

**难句本.tsv**：一句一行，13 列。

| 列 | 名字 | 内容 |
| --- | --- | --- |
| 1 | id | `slug-` 加 8 位编码（由原句算出） |
| 2 | 原句 | 照原文 |
| 3 | 注 | `word 释义；word 释义`，没有就空 |
| 4 | 试 | 问题 |
| 5 | 答 | 答案 |
| 6 | 主干 | 断句表里的粗体（主语、谓语），用 ` … ` 连起来 |
| 7 | 断句 | 各行用 ` / ` 连起来 |
| 8 | 顺读 | 各块用 `／` 连起来 |
| 9 | 卡点 | 练习句为空 |
| 10 | 译 | 练习句为空 |
| 11 | 结构 | 结构标签，空格隔开，标签里的空格去掉（`it占位`） |
| 12 | 出处 | `书名 第 2 章 句 1` |
| 13 | 类型 | `精讲`、`练习`、`卡句·词都认识`、`卡句·有生词`、`卡句·没说` |

**单词本.tsv**：一词一行，11 列。同一个词在两章各出现一次，就是两行。

| 列 | 名字 | 内容 |
| --- | --- | --- |
| 1 | id | `slug-c02-` 加词（小写，空格换成 `_`） |
| 2 | 词 | 词或短语 |
| 3 | 音标 | 读前的词和词条有；短语和注的词为空 |
| 4 | 词性 | 同上 |
| 5 | 释义 | 读前的词：本章里的意思；词条：词典行的释义；注：注里的释义 |
| 6 | 原句 | 这个词所在的原文句子；读前的词取本章第一次出现的那句 |
| 7 | 原句译 | 词条有，别的为空 |
| 8 | 章 | 单元号 |
| 9 | 类型 | `读前`、`词条`、`注` |
| 10 | 掌握 | 词条的 `会用` 或 `认得`；别的为空 |
| 11 | 级别 | 如 `B2`、`C1，估`、`未定级` |

`slug` 是 `设置.json` 里的卡片 id 前缀，没写就从书名里取。

id 重复时（同一个原句讲了两次，或同一章里同一个词注了两次），第二个起加 `-2`、`-3`。后缀按出现的先后排：删掉前面那条，后面那条就补上没有后缀的 id，原来的 `-2` 没了。这时 Anki 会把它当成原来那张卡更新，`-2` 那张卡留着没人管，要手动删。所以同一个词一章里只注一次。

## 从第二版升级

第一、二版的项目（`设置.json` 里没有 `"format": 3`）照旧能检查、合订、排 PDF，单词本也能出。难句本和卡句定位要第三版。

没有自动转换：断句表和顺读要重写。要升级某个第二版的项目：

1. `设置.json` 加 `"format": 3`，可以再加 `"slug"`。
2. 各单元的 `## 补充句` 改名 `## 卡句`。
3. 每个长难句和卡句按 `reference/句子.md` 补上结构、试、断句表、答，删掉「主干」。轻读单元连「怎么拆」一起删。
4. 轻读单元把「## 长难句」挪到「## 理解」前面。
5. 前言加回读那一句和 `## 句子结构` 表（见 `reference/前言模板.md`）。
6. 跑 `build.py check`，改到 0 个问题。
7. 审稿一轮，只审句子块。

轻读的数量也变了（长文）：理解 2–3 题改成 2 题，词条 3–4 条改成 2–3 条，长难句分成精讲句 2 句、练习句 2–3 句。短文的词条 3 条改成 2 条。升级后 check 按新数量报，第 6 步一起改。

## 不做的事

- 音频：不放有声书链接，不生成语音。有声书、TTS 自己找。
- 间隔复习、进度记录：单词本和难句本只汇总、导出，不记你学会了没有。复习交给 Anki 一类的工具。
- 句法树图：拆句只用断句表。
- 绑定某个阅读器 App：阅读器导出的划线，让它抄进 `卡句.txt`，不为哪个 App 写专门的解析。

## 运行要求

- **Markdown、难句本、单词本**：Python 3.9 以上，只用标准库。macOS、Linux、Windows 都行；Windows 上把命令里的 `python3` 换成 `python`。
- **PDF**：只支持 macOS。排版用 Google 官方的 chrome-headless-shell（没有界面的 Chrome，不会弹窗、不抢前台和键盘输入），第一次用之前安装一次：`python3 scripts/renderer.py install`（从 Google 官方地址下载，安装时先显示大小，装在 `~/Library/Caches/english-reader/`；`status` 查看，`remove` 卸载）。没装时 `build.py pdf` 会停下提示，不会去启动本机浏览器；坚持用本机 Chrome、Edge 等可以设 `ER_ALLOW_GUI_BROWSER=1`，排的时候会抢前台。另需 Xcode 命令行工具（`xcode-select --install`）；没有 swift 只是没有页码。字体默认用 macOS 自带的宋体、楷体、苹方和 Iowan Old Style，要换见下面「PDF 字体」。
- **词的级别**：随 skill 附带 CEFR-J、Octanove 词表和 ECDICT 词频子集，离线可用。出处和许可见 `scripts/data/README.md`。拿 demo 原文按 A2、B1、C1 三档摸底，读法建议都合理（A2：偏难，主要难在词；B1：配讲义读；C1：适合练拆句）。按词频估出来的级别，具体名词常偏高（如 cart、canary），挑读前词时用 `lexicon.py level` 再核一次。
- **词典核对**：先读 macOS 系统「词典」App 里的牛津英汉汉英词典和 Oxford Dictionary of English（没下载的在词典 App 的设置里勾选）；查不到或不是 macOS 时，联网查 dictionaryapi.dev（数据来自 Wiktionary）。不能联网时加 `--offline`。都用不了时，核对表标“未核对”。本地词典文件（MDX 等）暂不支持。

### PDF 字体

项目 `设置.json` 的 `fonts` 管 PDF 用什么字体（讲义和难句本都按它排）。三种写法：

- `null`：用默认字体。
- 一个目录（字符串）：目录里放 BookSong（书宋）、BookKai（书楷）的字体文件。原来的写法，照旧能用。
- 一个对象：四种字体各用什么。

```json
"fonts": {"宋体": "Songti SC", "楷体": "Kaiti SC", "黑体": "PingFang SC", "英文": "Iowan Old Style"}
```

- 宋体：正文的中文。楷体：顺读、译文。黑体：标题、页眉和小字。英文：英文、页码。
- 四个键都可以不写，没写的用默认。键也可以写 `song`、`kai`、`hei`、`en`。
- 值写系统字体的名字（family 名），或字体文件的路径（`.otf`、`.ttf`、`.ttc`，相对项目目录或绝对路径）。
- 值也可以是列表，前面的没有某个字就用后面的：`"楷体": ["STKaiti", "Kaiti SC"]`。
- 英文字体排在中文字体前面：英文和数字用英文字体，中文落到宋体或楷体。
- 还要用 BookSong 目录，加 `"目录": "字体目录"`。

本机有哪些字体、项目现在用的是什么：

```
python3 scripts/build.py fonts            # 列出本机字体，按宋体、楷体、黑体、英文衬线、英文无衬线大致分组
python3 scripts/build.py fonts 项目目录    # 另外列出这个项目四种字体各用什么，本机没有的标「!」
```

macOS 上用 swift 取字体列表（Xcode 命令行工具），没有 swift 用 `system_profiler`（要十几秒）；Linux 用 `fc-list`。分组按名字猜，仅供参考。排 PDF 时，写的字体本机没有会提示一行，照常排（Chrome 会换成别的字体）。`build.py check` 查 `fonts` 的写法：不认识的键、值的类型不对、文件不存在。

例子。macOS 自带的另一套：

```json
"fonts": {"宋体": "STSong", "楷体": "STKaiti", "黑体": "Hiragino Sans GB", "英文": "Palatino"}
```

Noto 字体（Linux 常见，macOS 上自己装了也能用）：

```json
"fonts": {"宋体": "Noto Serif CJK SC", "楷体": ["LXGW WenKai", "AR PL UKai CN"], "黑体": "Noto Sans CJK SC", "英文": "Noto Serif"}
```

Windows 的字体名是 SimSun、KaiTi、Microsoft YaHei、Georgia 这一类。注意 PDF 现在只支持 macOS：在 Linux、Windows 上 `build.py fonts` 能列字体，排 PDF 还不行。

  精读.md            精读单元的结构和规则

  前言模板.md        前言（出处、缩写、语法术语表、句子结构表）

  术语.tsv           修辞和叙事手法的中英对照，脚本读它

  source.py          把 epub、html、txt 转成按单元分的纯文本
  profile.py         摸底：篇幅、句长、长句和拆句候选、高于水平的词占多少、读前词候选

## 版权

`demo/` 里只放公有领域的文本。用这个 skill 给有版权的文章（现在的报刊、在版的书）做讲解，自己学习没有问题；讲义和难句本里有大量逐字引文，项目里的 `原文/` 更是全文，不要把这样的项目目录提交到公开的地方，排出来的 PDF 和导出的 TSV 也只自己用。

`scripts/data/` 里的数据文件各有自己的许可（见该目录的 README），和 skill 本身的许可分开。
